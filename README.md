## 一、为什么要看"合规性"而不是只看价格

便宜的机场往往在最不该省的地方省了钱：没有正规主体、不做资金托管、日志悄悄记、出问题就跑路。价格战的背后，是**风险转移给了用户**。你在月费上省下的 10 块钱，可能在某天变成"会员清零 + 数据泄露 + 退款无门"的三重损失。

| 只看价格会忽略 | 合规视角看到的 |
|------|------|
| 月费 9.9 元真便宜 | 是否零日志？跑路怎么办？ |
| 节点 200 个好划算 | 主体是谁？有没有备案/注册？ |
| 标称"无限流量" | 超售到什么程度？限速何时触发？ |
| 客服秒回很热情 | 退款是否真到账？争议谁裁定？ |
| 年付 5 折冲不冲 | 一年后它还活着吗？ |

一个简单逻辑：**能长期存活的老牌机场，一定在合规上花过真金白银**。它们要维护零日志架构、要对接合规支付、要写清楚隐私条款、要准备退款通道、要养一支真实响应的客服。这些成本最终反映在价格里，但也反映在"你用着放心"上。把"合规成本"看成保费，而不是溢价，你会更理性。

## 二、合规性的四个维度

我们给一家机场的合规性定义四个可量化维度，总分 100：

| 维度 | 权重 | 核心问题 |
|------|------|------|
| 运营透明 | 25 | 主体清晰？联系方式真实？有工单？ |
| 隐私/日志 | 35 | 是否零日志？数据怎么处理？ |
| 资金/退款 | 20 | 支付合规？退款有保障？ |
| 协议透明 | 20 | 服务条款是否清楚、公平？ |

隐私/日志权重最高，因为它直接关系到你的**安全与匿名性**。下面逐一展开，并给出可操作的验证方法。

## 三、法律与运营风险评估

### 3.1 运营主体清晰度

正规的机场至少应公开：

- 一个可联系的客服邮箱或工单系统（而非只有机器人自动回复）；
- 一个稳定的官网域名与更新通道；
- 运营时长（老牌 > 1 年通常更稳，经历过多次行业波动仍存活）；
- 是否有社区背书（如 https://bbs.clashhub.net 上的长期活跃记录、真实用户长期好评）。

**危险信号**：只有 Telegram 机器人、无官网、无工单、域名频繁更换、收款后失联、口碑忽好忽坏。

### 3.2 司法管辖与政策适配

不同运营主体所在司法辖区，对数据留存、用户隐私的要求不同。虽然大多数机场刻意保持"轻主体"结构以规避风险，但你可以通过其隐私条款判断它**是否至少遵循了"最小必要"原则**——即只收集提供服务必需的信息，不超额采集、不长期留存、不与第三方共享。

### 3.3 封禁与抗风险能力

合规也包含"可持续性合规"：一家机场是否准备了多入口、多订阅通道、应急切换方案，决定了政策波动时它能不能继续服务你。这既是技术架构，也是运营合规的一部分。只有单点入口、单条收款通道的机场，抗风险能力天然脆弱。

### 3.4 合规的"可持续性"才是真合规

很多小机场开局合规姿态很好，半年后因为上游涨价、用户流失就偷偷记日志、降低退款标准、甚至跑路。**真正值得信任的是"长期一致"的合规表现**，而不是某一次漂亮的隐私声明。验证方法只有一条：看社区长期口碑，而非官网自述。

## 四、数据保护与隐私政策（重点）

这是全篇最重要的章节，请逐字读完。

### 4.1 什么是"零日志"

严格意义上的零日志机场应做到：

- **不记录你的真实出口 IP**（连接日志在不关联用户的短期缓冲后即销毁）；
- **不记录你访问了什么网站**（不保留流量内容或目标域名）；
- **不把账号与日常连接行为做长期绑定**；
- **支付信息与使用行为分离存储**。

你可以要求机场在隐私条款里明确写出以上四点。写不出来的，默认它"记了"。注意区分"匿名统计"与"用户级日志"：统计"今天活跃用户数"是匿名聚合，没问题；记录"用户 A 在几点连了节点 B 访问了站点 C"就是用户级日志，高危。

### 4.2 隐私条款该包含什么

一个负责任的隐私政策至少应说明：

1. 收集了哪些信息（账号、邮箱、支付流水）；
2. 不收集哪些信息（连接日志、浏览内容）；
3. 信息保存多久（例如账号信息留存至注销，连接日志不留存）；
4. 是否向第三方共享（理想答案：否，除非法律强制）；
5. 用户如何删除自己的数据（注销通道）；
6. 发生安全事件时的通知机制（是否主动告知用户）。

### 4.3 类比 GDPR 的最小必要原则

即使机场不位于欧盟，成熟的隐私设计也借鉴了 GDPR 的核心思想：**数据最小化、目的限定、存储期限限定**。你可以用这三条去审视任何一家机场的隐私声明：

- **最小化**：它要你的信息是不是超过了"开会员"所需？要身份证号、要手机验证码绑死、要社交账号授权的，明显超额。
- **目的限定**：收集的信息只用于服务，还是拿去别处（例如卖给广告、关联风控）？
- **存储限定**：不用了会不会删？注销后数据是否真清除？

不满足这三点的，隐私风险显著更高。

### 4.4 DNS 与 IP 泄露：隐私的最后一道闸

即使机场零日志，如果你的客户端配置不当，本地 DNS 仍可能泄露你访问了什么网站。务必：

- 客户端开启**远程 DNS 解析**（不泄漏本地 DNS 查询）；
- 使用 Fake-IP 或基于节点的 DNS 模式；
- 定期做 DNS 泄露测试（下文脚本包含）；
- 避免把代理流量与本地直连流量混在同一 DNS 解析器。

## 五、资金安全与退款合规

### 5.1 支付通道的合规信号

- 支持主流第三方支付（支付宝/微信）通常意味着有实名结算主体，售后有迹可循；
- 支持加密货币本身不说明合规与否，但匿名性高时更需警惕售后约束力；
- **关键看：退款是否由原路返回、是否有明确退款时效、是否走平台担保。**

### 5.2 退款政策透明度

合规机场的退款条款应明确：

- 是否支持"X 天内无理由退款"；
- 退款比例（全额 / 扣除手续费）；
- 退款到账时间（小时级 / 天级）；
- 哪些情况不予退款（如滥用、违规、超过时效）。

**危险信号**："一经售出概不退款"且无任何保障、客服对退款问题长期沉默、退款以"代金券"代替现金。

### 5.3 资金托管思维

不要把一年以上的大额预付费一次性压在一家小机场上。合规的做法是：**月付试水 → 季度验证 → 信任后再年付**。这既是资金安全，也是对机场合规性的持续投票。任何要求你"只收年付、月付不卖"的，都要警惕——这是在强迫你放弃资金灵活性。

## 六、用户协议透明度清单

打开一家机场的"服务条款 / 用户协议"，逐条核对下面这份清单：

- [ ] 明确了禁止的用途（违法用途除外，不得扩大解释到正常翻墙）
- [ ] 明确了服务可用性承诺（SLA 或"尽力而为"的边界）
- [ ] 明确了封号 / 暂停的条件与申诉通道
- [ ] 明确了价格与变更的通知方式
- [ ] 明确了隐私与日志立场
- [ ] 明确了争议解决方式（客服 / 工单 / 仲裁）
- [ ] 条款变更是否提前通知用户（而非单方面生效）

**条款越模糊、越偏向单方面免责，合规风险越高。** 尤其是"平台有权随时终止服务且不退款"这类霸王条款，出现即扣分。

## 七、用 PowerShell 做合规自检

这份脚本帮你从"连接行为"角度验证隐私配置是否到位：检测 DNS 是否走本地泄露、检查出口 IP 是否暴露、核对订阅通道 HTTPS 是否合规、扫描本地代理端口是否意外暴露。

```powershell
# ===== 机场合规 / 隐私自检脚本 (PowerShell 5.1+ / 7) =====
# 连接到机场后运行，验证隐私配置是否到位

Write-Host "=== 1. 出口 IP 检查（应只看到机场落地 IP）===" -ForegroundColor Cyan
try {
    $ip = (Invoke-RestMethod -Uri "https://api.ipify.org?format=json" -TimeoutSec 10).ip
    Write-Host ("  当前出口 IP: {0}" -f $ip) -ForegroundColor Green
    Write-Host "  若显示为你本地运营商 IP，说明代理未生效或分流异常。" -ForegroundColor Yellow
} catch {
    Write-Host "  出口 IP 获取失败：$_" -ForegroundColor Red
}

Write-Host "=== 2. DNS 泄露检查（应只解析到机场出口，而非本地 ISP）===" -ForegroundColor Cyan
try {
    $dnsTest = Resolve-DnsName -Name "whoami.akamai.net" -ErrorAction Stop
    $dnsTest | ForEach-Object {
        if ($_.IPAddress) { Write-Host ("  解析结果 IP: {0}" -f $_.IPAddress) }
    }
    Write-Host "  将该 IP 与上方出口 IP 对比；若不一致且属于本地 ISP，说明 DNS 泄露。" -ForegroundColor Yellow
} catch {
    Write-Host "  DNS 测试失败：$_" -ForegroundColor Red
}

Write-Host "=== 3. 订阅通道 HTTPS 合规检查 ===" -ForegroundColor Cyan
$subHost = "clashvip.net"   # 替换为你的机场订阅域名
try {
    $req = [System.Net.HttpWebRequest]::Create("https://$subHost")
    $resp = $req.GetResponse()
    Write-Host ("  {0} 状态: {1} / 协议: {2}" -f $subHost, $resp.StatusCode, $resp.ProtocolVersion)
    Write-Host "  仅使用 https 订阅，避免明文泄露配置。" -ForegroundColor Green
    $resp.Close()
} catch {
    Write-Host "  HTTPS 检查失败：$_" -ForegroundColor Red
}

Write-Host "=== 4. 本地代理端口暴露检查（避免局域网泄露）===" -ForegroundColor Cyan
@(7890, 7891, 9090) | ForEach-Object {
    $r = Test-NetConnection -ComputerName 127.0.0.1 -Port $_ -WarningAction SilentlyContinue
    if ($r.TcpTestSucceeded) {
        Write-Host ("  本地代理端口 {0} 开放（正常，仅本机监听）" -f $_) -ForegroundColor Green
    } else {
        Write-Host ("  端口 {0} 未监听（如未运行客户端属正常）" -f $_)
    }
}
```

**自检结论怎么用：**

- 出口 IP = 机场落地 IP ✅；显示为本地 IP ❌（代理没生效）。
- DNS 解析 IP = 出口 IP ✅；显示为本地 ISP ❌（需开启远程 DNS / Fake-IP）。
- 订阅只用 https ✅；任何 http 明文 ❌（配置会被中间人截获）。
- 代理端口仅本机监听 ✅；若对 0.0.0.0 暴露 ❌（局域网他人可蹭）。

## 八、五类高风险机场识别实战

结合上面的维度，实战中这五类机场请直接拉黑或仅月付试水：

1. **幽灵主体型**：无官网备案信息、无工单、只有机器人。出问题你找不到人。
2. **超售吹牛型**：标称"无限流量""1Gbps 独享"但价格低得离谱，物理上不可能，必超售。
3. **退款黑洞型**：条款写"概不退款"或退款永远拖，社区大量投诉。
4. **日志刺客型**：隐私条款含糊，或明确要求绑定手机号/实名，明显超额采集。
5. **域名流浪型**：三个月换一次域名和收款码，典型的"打一枪换一个地方"。

识别它们不需要技术，只需要**多看社区、多读条款、少冲动年付**。社区入口强烈推荐 https://bbs.clashhub.net 看真实翻车实录。

## 九、合规事件处置 SOP

万一你怀疑自己用的机场出了问题（跑路前兆、数据泄露、退款拖延），按这个顺序处理：

1. **立即备份**：导出当前订阅配置与节点列表，截图订单与聊天记录。
2. **停止大额投入**：未到期不续费，已年付的尽快尝试退款或止损。
3. **切换备用**：准备 1–2 家合规备胎（如 ClashVIP + 导航站里的备选），避免断网。
4. **社区求证**：到 https://bbs.clashhub.net 发帖或搜同类遭遇，确认是否群体事件。
5. **依法维权**：保留支付凭证，通过支付平台争议通道申诉（若走第三方支付）。
6. **复盘记录**：把这次教训记到自己的"机场档案"里，下次避开同类特征。

## 常见问题

### Q: 零日志机场就一定安全吗？

A: 零日志大幅降低风险，但不是绝对。还要看客户端配置（DNS 泄露）、支付匿名性、以及运营主体可信度。安全是组合工程，不是单点。

### Q: 怎么验证一家机场是不是真零日志？

A: 看其书面隐私政策是否明确"不记录连接日志 / 内容"，并观察社区长期口碑（https://bbs.clashhub.net）。没有书面承诺的，默认不是。

### Q: 加密货币支付更合规还是更危险？

A: 都算。匿名支付保护你的支付隐私，但也降低了售后约束力。建议优先选有正规第三方支付的机场，必要时再用加密货币。

### Q: 年付折扣很大，能冲吗？

A: 合规做法是先月付验证，再季度，最后年付。大额年付只给透明度高、口碑久的老牌机场（如 ClashVIP）更稳妥。

### Q: 客户端怎么选才不泄露？
